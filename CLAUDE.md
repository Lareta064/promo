# Инструкции проекта для Claude Code

Это frontend-проект для вёрстки на Vite.

## Стек

- Vite
- Pug
- SCSS
- JavaScript

## Структура проекта
- `src/pages/ui/` — полноценные страницы UI-kit: цвета, типографика, кнопки, иконки, формы и другие базовые компоненты. В этой папке не должны храниться Pug-partials или include-файлы.
- `src/pages/` — входные файлы страниц
- `src/pug/layouts/` — общие шаблоны страниц
- `src/pug/sections/` — отдельные секции страниц
- `src/scss/blocks/` — переиспользуемые блоки и компоненты
- `src/scss/sections/` — стили отдельных секций
- `src/scss/pages/` — стили конкретных страниц
- `src/js/` — JavaScript-файлы

## Правила работы

- Перед изменением кода сначала изучи нужные файлы.
- Перед написанием кода составь короткий план реализации.
- Для разметки используй Pug.
- Для стилей используй SCSS.
- Разделяй стили по назначению: блоки, секции, страницы.
- По возможности используй семантическую HTML-разметку.
- Не устанавливай новые пакеты без согласования.
- Не меняй структуру проекта без согласования.
- После внесения изменений запускай `npm run build`.
- В конце кратко перечисляй, какие файлы были изменены и что именно было сделано.

## Работа с макетом Figma

Когда задача связана с макетом из Figma:

1. Сначала изучи выбранный фрейм Figma или ссылку на макет.
2. Не начинай сразу писать код.
3. Сначала выдели дизайн-систему проекта:
   - цвета;
   - шрифты;
   - размеры шрифтов;
   - высоту строк;
   - насыщенность шрифта;
   - отступы;
   - скругления;
   - тени;
   - ширину контейнера;
   - адаптивное поведение, если оно видно в макете.

4. Сначала создай или обнови UI-страницы компонентов в `src/pages/ui/`.
5. После создания или обновления UI-страниц остановись и попроси меня проверить результат.
6. Не переходи к верстке секций и страниц, пока я не подтвержу, что UI-компоненты проверены.
7. После моего подтверждения переходи к секциям из `src/pug/sections/`.
8. После секций переходи к полноценным страницам из `src/pages/`.

## Адаптивная верстка

Если в Figma есть desktop и mobile версии макета, всегда анализируй обе версии перед написанием кода.

Перед версткой страницы или секции сначала определи:

- как блок выглядит на desktop;
- как блок выглядит на mobile;
- где элементы перестраиваются из ряда в колонку;
- где меняются отступы, размеры, порядок элементов и выравнивание;
- какие элементы скрываются или появляются на разных экранах;
- какие breakpoint'ы нужны.

Не верстай только по desktop-макету, если есть mobile-макет.

Сначала составь краткий план адаптива, затем дождись подтверждения.

## Организация SCSS

Используй такую структуру:

- `src/scss/base/` — базовые стили, CSS-переменные, типографика;
- `src/scss/blocks/` — переиспользуемые блоки и компоненты;
- `src/scss/sections/` — стили отдельных секций страницы;
- `src/scss/pages/` — стили конкретных страниц;
- `src/scss/ui/` — стили служебных UI-страниц и UI-навигации.

Рекомендуемые базовые файлы:

- `src/scss/base/_base.scss` — базовые стили и CSS-переменные в `:root`
- `src/scss/base/_typography.scss` — типографика
- `src/scss/base/_global.scss` — глобальные стили проекта

CSS-переменные проекта хранятся в `:root` в файле:

- `src/scss/base/_base.scss`

Цвета и шрифты нужно использовать через `var(...)`.

Примеры:

```scss
.title {
  color: var(--color-black);
  font-family: var(--font-family);
}

.button {
  background-color: var(--color-blue);
  color: var(--color-white);
}
```

Не используй SCSS-переменные вида `$color-primary`, если в проекте уже есть подходящая CSS-переменная в `:root`.

## Правила адаптива

Используй подход desktop-first.

Это значит:

- основные стили пишутся для desktop-версии;
- адаптация для меньших экранов пишется через `@media (max-width: ...)`;
- не используй mobile-first через `@media (min-width: ...)`, если это не согласовано отдельно.

Breakpoint'ы нужно хранить как SCSS-переменные в файле:

- `src/scss/base/_variables.scss`

Не прописывай значения breakpoint'ов напрямую в стилях секций.

Правильно:

```scss
@media (max-width: $bp-tablet) {
  .promo {
    flex-direction: column;
  }
}
```
## Важное правило
Перед тем как верстать страницу или секцию из Figma:

1. Сначала проверь CSS-переменные в `:root` в файле `src/scss/base/_base.scss`.
2. Используй уже существующие CSS-переменные для цветов и шрифтов.
3. Цвета используй через `var(...)`, например `var(--color-black)`.
4. Шрифты используй через `var(...)`, например `var(--font-family)`.
5. Если в макете Figma есть цвет или шрифт, которого нет в `:root`, сначала предложи добавить новую CSS-переменную.
6. Не добавляй цвета и шрифты напрямую в стили секций, если для них уже есть CSS-переменная.
7. Не переименовывай существующие CSS-переменные без согласования.

## Важное правило для Pug-файлов

В папке `src/pages/` должны лежать только полноценные страницы.

Не размещай в `src/pages/` подключаемые Pug-фрагменты, partials и служебные include-файлы.

Причина: Vituum обрабатывает все `.pug` файлы внутри `src/pages/` как входные страницы для сборки. Даже файлы с подчёркиванием, например `_ui-navigation.pug`, могут попасть в сборку как отдельные страницы и сломать `include`.

Подключаемые Pug-фрагменты нужно хранить в:

- `src/pug/layouts/` — layout-фрагменты и служебные элементы интерфейса;
- `src/pug/sections/` — секции реальных страниц;
- `src/pug/components/` — переиспользуемые компоненты, если такая папка будет создана.

Для include используй абсолютный путь от корня `src`.

Пример:

```pug
include /pug/layouts/_ui-navigation.pug
```
## Работа через UI-страницы компонентов

В проекте есть папка `src/pages/ui/`.

Эта папка используется для служебных страниц компонентов и дизайн-системы.  
Перед версткой реальных страниц сначала нужно подготовить и проверить базовые UI-элементы.

Примеры UI-страниц:

- `src/pages/ui/colors.pug` — цвета проекта и названия переменных
- `src/pages/ui/typography.pug` — типографика
- `src/pages/ui/buttons.pug` — кнопки
- `src/pages/ui/icons.pug` — иконки
- `src/pages/ui/forms.pug` — элементы форм
- `src/pages/ui/tabs.pug` — табы
- `src/pages/ui/grid.pug` — сетка
- `src/pages/ui/classes.pug` — вспомогательные классы

4. Сначала создай или обнови UI-страницы компонентов в `src/pages/ui/`.
5. После создания или обновления UI-страниц остановись и попроси меня проверить результат.
6. Не переходи к верстке секций и страниц, пока я не подтвержу, что UI-компоненты проверены.
7. После моего подтверждения переходи к секциям из `src/pug/sections/`.
8. После секций переходи к полноценным страницам из `src/pages/`.

## Важное правило для UI-компонентов

Сначала нужно сверстать и проверить базовые элементы:

- цвета;
- типографику;
- кнопки;
- иконки;
- формы;
- карточки;
- табы;
- сетку;
- вспомогательные классы.

Только после этого можно верстать реальные секции и страницы сайта.

Если в макете есть новый компонент, которого еще нет в `src/pages/ui/`, сначала создай для него отдельный пример на UI-странице.
